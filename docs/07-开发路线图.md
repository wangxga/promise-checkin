# 07 - 开发路线图

> 项目：**如约打卡**（promise-checkin）
> 原则：**小步快跑，MVP 优先** —— 先把核心场景跑通上线，再迭代增强
> 最后更新：2026-06-22

---

## 一、里程碑总览

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  M0 立项准备  │  M1 MVP上线   │  M2 体验增强  │  M3 横向扩展  │
│   1~2 周      │   4~6 周      │   3~4 周      │   持续迭代    │
└──────────────┴──────────────┴──────────────┴──────────────┘
      │              │              │              │
      ▼              ▼              ▼              ▼
  备案/环境      兴趣班核心      提醒/数值      家庭共享
   就绪          跑通            等增强         商业化
```

| 阶段 | 目标 | 核心交付物 | 预计周期 |
|---|---|---|---|
| **M0** 立项准备 | 备案 + 环境 + 项目脚手架 | 可运行的空壳 + 备案通过 | 1~2 周（备案是关键路径） |
| **M1** MVP 上线 | 兴趣班核心流程跑通 | 可上架的小程序 | 4~6 周 |
| **M2** 体验增强 | 提醒 + 数值类 + 报告 | 量血压/吃药等场景可用 | 3~4 周 |
| **M3** 横向扩展 | 家庭共享 + 商业化 | 多人协作、会员体系 | 持续 |

---

## 二、M0 - 立项准备（1~2 周）

> ⚠️ **关键路径是 ICP 备案**，需 ~20 天，必须第一周就启动。

### 任务清单

| 编号 | 任务 | 负责域 | 备注 |
|---|---|---|---|
| M0-1 | 启动 ICP 备案（云服务商后台提交） | 运维 | **最优先**，卡全程 |
| M0-2 | 注册微信小程序账号，拿 AppID/AppSecret | 产品 | 个人主体即可 |
| M0-3 | 服务器初始化（Node/MySQL/Redis/Nginx/PM2） | 运维 | 跑 `install-env.sh` |
| M0-4 | monorepo 脚手架搭建（pnpm workspace） | 全栈 | `miniapp/` `server/` `shared/` |
| M0-5 | 前端：uni-app 项目初始化 + 路由 + 请求封装 | 前端 | |
| M0-6 | 后端：Koa2 + TS + Prisma + 中间件骨架 | 后端 | 含错误处理、日志、鉴权中间件 |
| M0-7 | 数据库初始化（建库建表，跑 DDL） | 后端 | 见 03-数据库设计 |
| M0-8 | 跑通最小闭环：登录接口 + 前端能调通 | 全栈 | 验证整条链路 |

**M0 验收标准**：前端能调通后端登录接口，数据库有用户表，整个技术链路通畅无卡点。

## 三、M1 - MVP 上线（4~6 周）

> 核心目标：**让一个家长能用本产品完整管理孩子的兴趣班打卡。**

### Sprint 1（2 周）：后端核心接口

| 编号 | 任务 | 产出 |
|---|---|---|
| M1-1 | 微信登录鉴权完整实现 | `/auth/login`、`/auth/refresh`、JWT 签发/校验 |
| M1-2 | 计划 CRUD 接口 | `/plans` 全套接口 + 参数校验 |
| M1-3 | 打卡 CRUD 接口 | `/checkins` 全套 + upsert 语义 |
| M1-4 | 排期生成定时任务 | 每日为 fixed 计划生成 pending 槽位 |
| M1-5 | 统计接口 | `/stats/overview`、`/plans/:id/progress` |
| M1-6 | used_count 事务一致性 | 写打卡走事务 + 每日校对任务 |
| M1-7 | 后端单元测试（核心逻辑） | Jest + 覆盖率 > 60% |

### Sprint 2（2 周）：前端核心页面

| 编号 | 任务 | 产出 |
|---|---|---|
| M1-8 | 登录页 | 微信一键登录 + token 持久化 |
| M1-9 | 首页（今日待办 + 计划列表） | 进度条卡片、下拉刷新 |
| M1-10 | 新建/编辑计划（分步表单） | 含图标/颜色/排期选择 |
| M1-11 | 计划详情页（进度环 + 日历） | Canvas 进度环、月历组件 |
| M1-12 | 一键打卡 + 标记请假 | 底部操作面板、快捷备注 |
| M1-13 | 缺席列表 + 备注编辑 | 可补备注"回想原因" |
| M1-14 | 个人中心（资料、退出登录） | |

### Sprint 3（1~2 周）：联调测试与上架

| 编号 | 任务 | 产出 |
|---|---|---|
| M1-15 | 前后端联调，修 bug | 全流程跑通 |
| M1-16 | 微信真机测试 | 至少 3 机型覆盖 |
| M1-17 | 性能优化 | 列表虚拟滚动、图片懒加载 |
| M1-18 | 备案完成 → 部署上线 | HTTPS、PM2、备份就位 |
| M1-19 | 提交微信审核上架 | 准备截图、说明、隐私协议 |
| M1-20 | 自用 dogfooding（自己先用 2 周） | 收集真实使用问题 |

**M1 验收标准**（对应需求文档）：
> 一个家长能录入孩子的兴趣班，每次上课后一键打卡，请假时标记原因，随时打开小程序就能看到「上了多少节、还剩多少节、哪天没去、为什么没去」。

## 四、M2 - 体验增强（3~4 周）

> 核心目标：**覆盖更多场景（量血压/吃药）+ 提升留存（提醒推送）。**

### 任务清单

| 编号 | 任务 | 价值 |
|---|---|---|
| M2-1 | 数值记录功能（前端表单 + 趋势折线图） | 解锁量血压/血糖/背单词等场景 |
| M2-2 | 微信订阅消息推送（该打卡了） | 提升留存核心手段 |
| M2-3 | 提醒规则配置（每计划可设提醒时间） | |
| M2-4 | 多端适配优化（H5 编译发布） | 便于分享给非微信用户 |
| M2-5 | 月度/季度报告导出（图片/PDF） | 用户价值感、传播点 |
| M2-6 | 数据可视化增强（计划对比、热力图） | 深度统计页 |
| M2-7 | 离线打卡队列（弱网友好） | 体验细节 |
| M2-8 | 回收站（30 天内恢复已删除计划） | 防误操作 |

## 五、M3 - 横向扩展（持续）

### 任务清单（按价值排序）

| 编号 | 任务 | 价值 |
|---|---|---|
| M3-1 | 家庭体系（建家庭、邀请家人） | 切入"共同管理孩子课"高频场景 |
| M3-2 | 计划成员（一个计划下区分大宝/二宝） | 多娃家庭刚需 |
| M3-3 | 计划模板库（常见兴趣班/药品预设） | 降低新用户上手成本 |
| M3-4 | 数据导入/导出（Excel） | 数据可移植、信任感 |
| M3-5 | 多语言（i18n） | 海外华人用户 |
| M3-6 | 商业化：免费版限 3 计划 + 会员无限 | 变现路径 |
| M3-7 | App 版本（uni-app 编译到 iOS/Android） | 跨出微信生态 |
| M3-8 | 数据分析看板（后台管理） | 运营支撑 |

## 六、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| ICP 备案被驳回/延误 | 中 | 高 | 提交前仔细核对材料，留 buffer；备案期间用开发版推进编码 |
| MVP 周期超预期 | 高 | 中 | 严格砍 P1/P2 功能；每周 demo，及时收缩范围 |
| 兴趣班场景用户量小 | 中 | 中 | M2 尽快上数值类（量血压）扩品类；用分享激励拉新 |
| 微信审核被拒 | 中 | 中 | 提前研究审核规则；准备好隐私协议、类目资质 |
| 自建服务器运维负担 | 中 | 中 | 全套脚本化、监控告警完善；必要时 M3 迁移到云托管 |

## 八、成功标准（每个里程碑）

| 里程碑 | 成功标准 |
|---|---|
| M0 | 备案通过 + 空壳能登录 + 数据库就绪 |
| **M1 MVP** | **自己能连续 2 周真实用它管理孩子兴趣班**，且愿意推荐给同事 |
| M2 | 量血压/吃药场景也能流畅使用；订阅消息推送到达率 > 90% |
| M3 | 家庭共享能跑通；月活 > 500（自传播带来的真实用户） |

> 最关键的验证点是 **M1 的自用 dogfooding**——如果连自己都不愿意每天用，说明产品没价值，必须停下来反思，而不是继续往后做。
