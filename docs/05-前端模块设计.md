## 一、页面结构与导航

底部 TabBar 三栏（职责分离，避免重复）：

```
┌─────────────────────────────────────────────┐
│                                             │
│              （页面内容区）                   │
│                                             │
├──────────────┬──────────────┬───────────────┤
│   今日        │   计划        │   我的        │
│   打卡操作     │   计划管理     │   个人中心    │
└──────────────┴──────────────┴───────────────┘
```

**设计原则**：今日 = 做事（纯打卡操作），计划 = 管理（列表+新增），零内容重叠。

### 完整页面清单

| 页面 | 路径 | 说明 | 在 TabBar |
|---|---|---|---|
| 登录页 | `pages/login/index` | 微信一键登录 | - |
| 今日 | `pages/today/index` | 今日待办 + 一键打卡 + 已完成 | ✅ |
| 计划 | `pages/plan/index` | 计划卡片列表（进度）+ 标题栏「+」新增 | ✅ |
| 计划详情 | `pages/plan/detail` | 进度/日历/记录 三 Tab | - |
| 新建/编辑计划 | `pages/plan/edit` | 4 步分步表单 | - |
| 缺席记录 | `pages/stats/missed` | 跨计划缺席汇总 | - |
| 我的 | `pages/me/index` | 用户信息、退出登录 | ✅ |

> 路由配置在 `pages.config.ts`（由 `@uni-helper/vite-plugin-uni-pages` 自动生成 `pages.json`）。
> TabBar 配置在 `pages.config.ts` 的 `tabBar` 字段。`homePage: 'pages/today/index'` 强制今日为首页。

## 二、今日页（纯打卡操作）

**职责**：只管"今天要打什么卡"，不含计划管理。

**数据来源**：`GET /stats/overview`（`checkinStore.fetchOverview`）

**布局**：
- 今日待办区：每条 = 计划色点 + 名称 + 时间 + [打卡] 按钮，点击卡片或按钮即一键打卡
- 已完成区：半透明显示今日已打的卡
- 缺席入口：底部"查看 N 条缺席记录"按钮（有缺席时显示）

**交互**：
- 点待办卡片/按钮 → `checkinStore.quickDone`（POST upsert done）→ 本地更新概览（todo-1, done+1）+ toast + 震动
- 打卡失败 → toast 错误信息

---

## 三、计划页（列表管理）

**职责**：所有计划的列表 + 进度展示 + 新增入口。

**数据来源**：`GET /plans?status=active`（`planStore.fetchPlans`）

**布局**：
- 顶部：标题"我的计划" + 右上角圆形「+」按钮（新增入口）
- 计划卡片：类型首字图标（带主题色背景）+ 名称 + 类型/起始进度 + 右侧进度文字（剩 N · XX%）+ 底部进度条
- 空状态：虚线圆 + "还没有计划" + 新建按钮

**交互**：
- 点卡片 → 跳详情页 `pages/plan/detail?id=X`
- 点「+」→ 跳新建页 `pages/plan/edit`

**进度展示**（`utils/progress.ts`）：
- 有限计划：显示 `剩 N · XX%`，进度条宽度 = progress
- 无限计划：显示 `已完成 N 次`，进度条满宽半透明

## 四、计划详情页（Tab 三栏）

**职责**：单计划的深度查看。

**数据来源**：`GET /plans/:id` + `GET /plans/:id/progress` + `GET /plans/:id/checkins/calendar`

**布局**：顶部摘要区 + Tab 三栏切换

- **摘要区**：图标（类型首字 + 主题色）+ 计划名 + 类型/备注
- **Tab 进度**（默认）：
  - 2×2 统计宫格：已完成（含起始进度）/ 缺席 / 已消耗配额（含缺席或仅完成的标注）/ 剩余
  - 无限计划：显示 ∞ + 连续天数
  - 信息卡：连续打卡 / 完成率 / 预计完成日期
  - "编辑计划"文字入口
- **Tab 日历**：
  - 月历（周一起），每天格子显示状态点（绿=完成/红=缺席/灰=待打）
  - 今日格子高亮（黑底白字）
  - 左右箭头切月份
  - 底部图例
- **Tab 记录**：
  - 缺席记录列表（日期 + 备注 + "已补/缺"标签）

## 五、新建/编辑计划（分步表单）

**职责**：创建或编辑计划，4 步分步表单降低认知负担。编辑模式复用同一表单（`?id=X` 时加载数据回填）。

**步骤**：

| 步骤 | 字段 |
|---|---|
| Step 1 基本信息 | 计划名称、类型（6 选 1）、主题色（8 色点选） |
| Step 2 次数与配额 | 次数（有限/无限）、总次数、**起始进度**、**缺勤是否计消耗(switch)**、**逾期处理(保留/自动缺席)**、宽限期、开始日期 |
| Step 3 时间模式 | 固定/不固定、排期方式（按周几/每天定时）、每周哪几天（多选）、时间（可多个增删）、记录数值(switch)+单位 |
| Step 4 备注 | 备注文本框 |

**校验**（提交时）：
- 名称非空
- 起始进度 ≤ 总次数
- fixed 模式：选了周几且加了时间

**提交**：`POST /plans`（新建）或 `PUT /plans/:id`（编辑），成功后 `navigateBack`。

> 注：旧设计的"按 type 智能联动默认配置"（course 默认有限+固定等）**M1 未实现**，所有类型初始值固定。待后续迭代。

## 六、组件策略

**M1 不抽独立组件**，所有 UI 在页面内联实现（view + scss）。原因：页面不多，内联更直观，避免过度抽象。

**UI 库**：**wot-design-uni**（不是 uni-ui）。通过 easycom 自动引入（`pages.config.ts` 配置 `^wd-(.*)` 规则）。
- 已用组件：`wd-button`（打卡/操作按钮）、`wd-loading`（加载态）
- 后续可按需引入：`wd-popup`（底部弹层）、`wd-calendar`（日历）等

**状态颜色规范**（iOS 风格，比旧 Material 色板更克制）：
| 状态 | 颜色 | 用途 |
|---|---|---|
| done | `#34C759` 绿 | 已完成 |
| missed | `#FF3B30` 红 | 缺席 |
| pending | `#C7C7CC` 灰 | 待打卡 |
| 今日待办 | 计划自身 color | 用计划色区分 |
| 调整排期 | `#007AFF` 蓝 | 标记"改" |
| 补录 | `#AF52DE` 紫 | 标记"补" |

## 七、状态管理（Pinia）

Store 文件在 `src/store/`，共 4 个：

| Store | 文件 | 职责 | 持久化 |
|---|---|---|---|
| **token** | `token.ts` | accessToken / refreshToken / isLogin | ✅ persist（uni storage） |
| **user** | `user.ts` | profile / login() / fetchProfile() / restoreToken() / logout() | ❌（启动时 restoreToken 拉） |
| **plan** | `plan.ts` | plans[] / fetchPlans() / createPlan() / updatePlan() / archivePlan() / deletePlan() | ❌ |
| **checkin** | `checkin.ts` | overview / fetchOverview() / quickDone() | ❌ |

**设计要点**：
- `token` 独立成 store（持久化），`user` 不持有 token，通过 `useTokenStore()` 间接访问。
- `checkin.quickDone()` 打卡后**本地更新 overview**（todo-1, done+1），避免重新拉取，体验流畅。
- 没有 `stats` store——overview 数据进 checkin store，progress 数据在详情页本地 ref，missed 列表页直接调 api。
- 详情页的 plan/calendar 数据用页面本地 ref（不经 store），因为它是页面级临时数据。

**持久化**：`pinia-plugin-persistedstate` + uni storage 适配（`main.ts` 注册）。只有 token store 开启 persist。

## 八、请求封装

`src/http/` 目录：
- `http.ts`：核心 `request<T>()` 函数 + `http.get/post/put/del` 便捷方法
- `interceptor.ts`：`uni.addInterceptor` 注入 token（`Authorization: Bearer <token>`）
- `types.ts`：请求配置类型

**特性**：
- 统一注入 token + `X-Client: miniapp` header
- 业务错误码处理（code !== 0 抛 ApiError）
- 401 自动跳登录页（带防抖）
- 网络异常 toast 提示
- 泛型类型安全

## 十、路由守卫

`src/router/interceptor.ts`：拦截 `navigateTo/redirectTo/reLaunch/switchTab`。
- 白名单：`/pages/login/index`
- 未登录访问受保护页 → reLaunch 到登录页

`App.vue` 的 `onLaunch` 调 `userStore.restoreToken()`：
- 有 token → fetchProfile 验证（失效则清 token + 跳登录）
- 无 token → reLaunch 到登录页

## 十一、分层架构总结

```
页面（渲染 + 交互）
  ↓ 调用
store（状态 + 缓存 + 本地更新优化）
  ↓ 调用
api（发请求 + 类型转换）
  ↓ 走
http（token 注入 + 错误处理 + 401 跳转）
```

**解耦原则**：
- 页面不直接发请求，走 store
- API 层只管请求 + 类型，零业务逻辑
- Store 管状态，复杂派生用 utils 纯函数
- HTTP/路由/token 复用封装，不重复造轮子
