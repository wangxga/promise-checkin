# 生产部署指南

> 域名：`checkin.itwxg.com`（DNS 已解析，已有 SSL 证书）
> 服务器：阿里云 Linux，宿主机有 Nginx，MySQL + Redis + 后端用 Docker 启动

---

## 整体架构

```
微信小程序
  ↓ HTTPS 请求
宿主机 Nginx（443，SSL 证书 + 限流 + 反代）
  ↓ http://127.0.0.1:3001（宿主机端口；容器内监听 3000）
Docker 容器：后端 API（checkin-backend:v1.0）
  ↓
Docker 容器：MySQL 8.0 + Redis 7
```

---

## 数据库迁移（自动还是手工？）

**自动的。** 后端容器启动时会自动执行 `prisma migrate deploy`，它会：
- 首次部署：自动建所有表（users / plans / checkins）
- 后续更新：自动应用新的 migration（你改了 schema.prisma 并生成了 migration 后，重新构建镜像部署即可，不需要手工操作数据库）

所以你不需要手工建表。

## 第一章：在本地构建并导出镜像

### 步骤 1：编译 TypeScript 确认无误

```bash
cd /Users/wxg/wangxg/code/promise-checkin
pnpm install
pnpm --filter @promise-checkin/server build
```

确认 `packages/server/dist/` 下有编译产物，没有报错。

**这步在做什么**：本地先验证代码能编译通过，避免打包镜像后才发现编译错误。

### 步骤 2：生成数据库迁移（如果有 schema 变更）

```bash
cd packages/server
npx prisma migrate dev --name 你的迁移名    # 开发环境生成 migration
```

确认 `prisma/migrations/` 下有 migration 文件夹。

> 如果没改过 schema.prisma，跳过这步。

**这步在做什么**：Prisma 把你对数据库结构的变更（加字段、改类型等）记录成 migration 文件。部署时后端容器会自动执行这些文件来更新数据库表结构。

### 步骤 3：构建 Docker 镜像

```bash
cd /Users/wxg/wangxg/code/promise-checkin

# 运行构建脚本（Mac/Linux）
./packages/docker/scripts/build.sh v1.0

# Windows PowerShell
# .\Docker\scripts\build.ps1 v1.0
```

脚本会：
1. 用 `--platform linux/amd64` 构建镜像（适配阿里云 x86 服务器）
2. 构建完成后问你是否导出 .tar 文件 → 输入 `y`
3. 生成 `docker-images/checkin-backend-v1.0.tar`

**这步在做什么**：把后端代码 + 依赖 + Prisma migration 打包成一个 Docker 镜像。`--platform linux/amd64` 确保镜像能在阿里云服务器（x86 架构）上运行，即使你本地是 Apple Silicon（ARM 架构）。导出为 .tar 文件方便手工上传。

## 第二章：在服务器上部署

### 步骤 4：上传文件到服务器

```bash
# 上传镜像文件
scp docker-images/checkin-backend-v1.0.tar root@你的服务器IP:/opt/promise-checkin/

# 上传 Docker 配置（docker-compose.yml + 构建脚本）
scp -r packages/docker/ root@你的服务器IP:/opt/promise-checkin/

# 上传 .env.production
scp packages/server/.env.production root@你的服务器IP:/opt/promise-checkin/docker/
```

**这步在做什么**：把构建好的镜像和配置文件传到服务器上。

### 步骤 5：导入镜像

SSH 登录服务器后：

```bash
cd /opt/promise-checkin
docker load -i checkin-backend-v1.0.tar
```

验证：
```bash
docker images | grep checkin-backend
# → checkin-backend   v1.0   xxx   xxxMB
```

**这步在做什么**：`docker load` 把 .tar 文件恢复成 Docker 镜像。导入后 `docker images` 能看到这个镜像。

### 步骤 6：配置生产环境变量

```bash
cd /opt/promise-checkin/docker
vim .env.production
```

**必须修改的值**：

| 变量 | 改成什么 | 怎么生成 |
|---|---|---|
| `MYSQL_PASSWORD` | 一个强密码 | `openssl rand -hex 16` |
| `MYSQL_ROOT_PASSWORD` | 另一个强密码 | docker-compose.yml 里也要改一致的 |
| `JWT_SECRET` | 32 位以上随机密钥 | `openssl rand -hex 32` |
| `WX_APPID` | 你的小程序 AppID | 微信公众平台获取 |
| `WX_SECRET` | 你的小程序 Secret | 微信公众平台获取 |
| `DEV_AUTO_LOGIN` | **false** | 生产必须关闭 |

> **注意**：`DATABASE_URL` 和 `REDIS_HOST` 不用改，docker-compose.yml 会自动覆盖，指向 Docker 内部的 mysql 和 redis 容器。

同时修改 `docker-compose.yml` 里的 MySQL 密码，和 `.env.production` 一致：

```bash
vim docker-compose.yml
# 找到 MYSQL_ROOT_PASSWORD 和 MYSQL_PASSWORD，改成和 .env.production 一致的密码
```

**这步在做什么**：`.env.production` 是后端运行时读取的配置。包含数据库密码、JWT 密钥、微信凭证。不提交 git，只在服务器上存在。

### 步骤 7：启动所有服务

```bash
cd /opt/promise-checkin/docker
docker compose up -d
```

首次运行会：
1. 下载 MySQL 8.0 和 Redis 7 镜像（约 500MB）
2. 启动 checkin-mysql、checkin-redis、checkin-api 三个容器
3. 后端启动时自动执行 `prisma migrate deploy`（建表）
4. 后端映射到宿主机 3001 端口（容器内监听 3000）

**这步在做什么**：`docker compose up` 读取 `docker-compose.yml`，一键启动 MySQL + Redis + 后端。三个容器在 Docker 内部网络互相通信。`-d` 表示后台运行。

### 步骤 8：验证

```bash
# 容器状态（三个都应该是 Up / healthy）
docker compose ps

# 后端日志（确认没有报错，dev 后门应未开启）
docker compose logs api | head -20

# 健康检查
curl http://127.0.0.1:3001/health
```

预期：
```json
{"code":0,"data":{"status":"ok","deps":{"db":true,"redis":true}}}
```

- `db: true` = MySQL 连通
- `redis: true` = Redis 连通
- 日志里**不应**出现 `[dev] 已开启后门`

### 步骤 9：配置 Nginx

配置文件不随仓库分发，直接在宿主机上创建：

```bash
vim /etc/nginx/conf.d/checkin.conf
```

粘贴以下完整配置（**两处 ssl_certificate 路径改成你实际的证书路径**）：

```nginx
# 限流定义必须放 http 层级（conf.d/*.conf 被 include 在 http 内，放在文件顶部即可）
limit_req_zone $binary_remote_addr zone=checkin_api:10m rate=20r/s;

server {
    listen 80;
    server_name checkin.itwxg.com;
    # HTTP → HTTPS 强制跳转
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name checkin.itwxg.com;

    # ====== SSL 证书（改成你的实际路径）======
    ssl_certificate     /etc/nginx/ssl/checkin.itwxg.com.pem;
    ssl_certificate_key /etc/nginx/ssl/checkin.itwxg.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # 安全头
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;

    # API 反向代理 → Docker 里的后端（宿主机 3001 端口）
    location /api/ {
        limit_req zone=checkin_api burst=40 nodelay;

        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_send_timeout 30s;
        proxy_read_timeout 30s;
    }

    # 上传的静态文件（头像等）。由后端 koa-static 托管（已带 30 天缓存头），
    # 小程序 <image> 请求不带鉴权 header，必须公开访问
    location /uploads/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        access_log off;
    }

    # 健康检查（不限流，供监控用）
    location /health {
        proxy_pass http://127.0.0.1:3001;
        access_log off;
    }

    # 日志
    access_log /var/log/nginx/checkin-access.log;
    error_log  /var/log/nginx/checkin-error.log;
}
```

测试 + 重载：

```bash
nginx -t && systemctl reload nginx
```

验证 HTTPS：
```bash
curl https://checkin.itwxg.com/health
# → 和上面一样的 JSON
```

**这步在做什么**：Nginx 接收微信小程序的 HTTPS 请求，转发到后端的 3001 端口。

### 步骤 10：设置开机自启

```bash
systemctl enable docker
```

服务器重启后 Docker 自动启动 → 容器自动启动（配了 `restart: always`）。

## 第三章：小程序发布

### 步骤 11：配置前端 API 地址

本地开发机上：
```bash
cd packages/miniapp
vim env/.env.production
```
内容：
```
VITE_SERVER_BASEURL=https://checkin.itwxg.com/api/v1
```

### 步骤 12：编译生产版

```bash
cd packages/miniapp
pnpm build:mp-weixin
```

产物在 `dist/build/mp-weixin/`。

### 步骤 13：微信开发者工具上传

1. 导入 `packages/miniapp/dist/build/mp-weixin`
2. AppID 填真实 AppID
3. 详情 → 本地设置 → **取消勾选**"不校验合法域名"
4. 点**上传** → 填版本号 1.0.0 → 确认

### 步骤 14：配置服务器合法域名

mp.weixin.qq.com → 开发管理 → 开发设置 → 服务器域名 → request 合法域名：
```
https://checkin.itwxg.com
```

### 步骤 15：提交审核

mp.weixin.qq.com → 版本管理 → 提交审核 → 等待 1-3 个工作日 → 审核通过后发布。

## 后续更新流程

代码改了后，重新部署只需：

```bash
# 本地
./packages/docker/scripts/build.sh v1.1              # 构建新版本镜像
scp docker-images/checkin-backend-v1.1.tar root@服务器IP:/opt/promise-checkin/

# 服务器
cd /opt/promise-checkin
docker load -i checkin-backend-v1.1.tar
cd Docker
# 修改 docker-compose.yml 里的 image: checkin-backend:v1.1
docker compose up -d                         # 自动滚动更新
```

数据库会自动执行新的 migration（如果你改过 schema 并生成了新的 migration）。
